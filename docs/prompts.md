# Prompt 与审查记录

本文只记录本项目实际发生过的需求选择与审查修正。`原始 Prompt` 中标为“原话”的内容是短句节选；其余均明确标为上下文摘要，不把摘要伪装成逐字对话，也不补写未发生的长对话。

## Prompt 1：采用 SDD 并确定实施范围

- 场景：项目启动时，需要先决定开发方法、交付范围和实施组织方式。
- 原始 Prompt：用户原话：“阅读下这个项目，然后我们需要以SDD的模式来开发这个项目”；后续选择完整加分范围，并以“1”选择采用 subagent-driven 的实施方式（选择摘要）。
- AI 建议摘要：先形成可审查的设计规格和逐任务实施计划，把 Docker、核心撮合测试和断线重连纳入同一验收边界，再按任务边界实施和复核。
- 我的审查：人工/控制器确认题目基本功能与全部加分项都应进入范围，同时要求每个任务留下独立质量证据，不能以未验证的文档结论替代运行结果。
- 最终调整：建立 SDD 设计与计划文档，按任务边界推进；最终质量门统一覆盖 lint、类型检查、单元/集成测试、构建、E2E 和 Docker 接受检查。

## Prompt 2：真实用户、系统流动性与资产边界

- 场景：设计阶段需要同时解决“真实用户如何互相成交”“单人演示如何稳定产生成交”以及资产安全问题。
- 原始 Prompt：用户选择“真实用户 + 系统流动性”“严格冻结”“模块化单体”（选择摘要）。
- AI 建议摘要：真实用户共用按价格—时间优先的订单簿，内部系统账户在参考价两侧持续挂三档订单；买单冻结完整限价金额、卖单冻结完整数量，并把撮合、结算和事件提交放在同一进程调用链。
- 我的审查：人工/控制器核验系统账户不能获得特殊撮合优先级，真实用户不得透支、做空或自成交；系统流动性必须复用普通订单与结算路径，而不是绕开领域规则。
- 最终调整：采用模块化单体与混合流动性；真实用户触发 STP 时取消新订单剩余量并释放冻结资产，系统账户仍遵守普通价格—时间排序但免于真实用户 STP。

## Prompt 3：专业交易终端界面

- 场景：在多个界面方向中确定最终信息架构和视觉密度。
- 原始 Prompt：用户原话：“我认为B更好”，选择专业终端方案（短句节选）。
- AI 建议摘要：桌面端采用股票列表、交易区、资产区三栏布局，底部集中委托、持仓和成交；窄屏转为纵向布局，同时保留行情、下单、资产与活动记录的可访问性。
- 我的审查：人工/控制器要求界面不仅像终端，还必须能完成完整交易路径；涨跌不能只靠颜色表达，下单失败要保留输入，服务器状态才是余额和成交的权威来源。
- 最终调整：实现响应式专业交易终端、中文证券涨跌语义、明确的 WebSocket 状态，以及最佳买卖价快捷填单和可访问的委托/持仓/成交标签页。

## Prompt 4：撮合、结算与行情审查修正

- 场景：Task 4～5 的实现审查发现，单元行为通过并不足以证明私有事件边界、ID 契约和周期更新的整体正确性。
- 原始 Prompt：控制器审查摘要：裁决成交事件必须只投递给相关真实用户；后续要求核验 UUID 契约和一次完整 tick 的原子可观察结果。
- AI 建议摘要：保留 `trade.created` 已有的私有 audience 契约，即分别向买卖相关用户发布（双方相同时只发布一次）；使用契约兼容的 UUID；让行情推进、旧系统单撤销、新流动性补充、最佳价更新和事件发布形成一个完整市场周期。
- 我的审查：控制器通过针对性测试检查无关用户不会收到私有成交、生成 ID 能通过共享 schema，并纠正“长时间运行”测试只重复固定时刻、不能证明保留窗口推进的证据缺口。
- 最终调整：Task 4 裁决保留既有私有 trade audience，未因此修改代码；Task 5 改用 UUID 并强化完整 tick 的原子提交与故障恢复测试，同时让长期历史测试实际推进时间。以上均可由对应报告、修正提交与测试追溯。

## Prompt 5：前端恢复、静态安全与 E2E 稳定性

- 场景：Task 10～12 审查覆盖命令不确定性、会话失效、生产静态托管边界和断线重连测试的确定性。
- 原始 Prompt：控制器审查摘要：Task 10 要求幂等重试与 `401` 终止处理；Task 11 要求拒绝 encoded dot 静态路径探测；Task 12 要求消除 E2E 重连 jitter 带来的时序不确定性。
- AI 建议摘要：网络结果不确定时复用同一 `clientOrderId`，输入改变后再生成新 ID；`401` 时停止连接并清理身份；静态回退前解码并拒绝点段探测；E2E 构建固定重连抖动而保留生产随机抖动。
- 我的审查：控制器用失败路径测试区分“可安全重试”和“必须终止”，用编码路径回归测试验证 SPA fallback 不泄露边界，并确认测试专用确定性配置没有改变生产模式。
- 最终调整：Task 10 加固幂等命令状态与未授权处理，Task 11 拒绝 encoded dot 探测，Task 12 仅在 E2E mode 固定 jitter；这些是实际发生的审查修正摘要，不代表虚构的逐字对话。
